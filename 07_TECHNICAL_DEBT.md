# StrikeNova — Technical Debt

This is a living register. Do not treat every item as a defect; some are architectural cleanup or verification tasks.

## Current / Potential Debt

1. Project architecture and implementation need a periodic reconciliation audit.
2. Historical conversational decisions should be progressively promoted into structured decision records.
3. Research indicators need clear separation between experimental and production-grade analytics.
4. Market-data provider differences should be isolated behind normalized interfaces where practical.
5. Live trading requires stronger operational controls than paper trading.
6. Deployment architecture should be finalized only after current usage, cost and reliability requirements are measured.
7. Documentation should remain synchronized with implementation after each major phase.

## Debt Management Rule

Do not accumulate documentation debt by allowing major architectural changes to remain only in chat. Update the relevant memory documents as part of the change workflow.
